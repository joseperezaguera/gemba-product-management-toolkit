# Plan 01-01: Faceted Search Backend

**Phase:** 1 — Faceted Search Backend
**Phase goal:** El endpoint `/search` extiende su respuesta con un campo `facets` para queries ambiguas, manteniendo latencia p99 ≤200ms.

## Tasks

- [ ] **DETECT-01**: Implementar clasificador de ambigüedad por dispersión de categorías en top-K resultados
- [ ] **DETECT-02**: Añadir feature flag `search.facets.ambiguity_threshold` configurable en runtime
- [ ] **DETECT-03**: Optimizar el clasificador para <10ms p99 sin afectar la latencia del response
- [ ] **FACET-01**: Implementar generación de facetas (3-5 por query ambigua) basada en atributos de productos
- [ ] **FACET-02**: Calcular poder discriminatorio (entropía normalizada) y seleccionar las 3-5 facetas con mayor valor
- [ ] **FACET-03**: Ordenar facetas por uso histórico (consulta `facet_usage_stats`); las más usadas primero
- [ ] **FACET-04**: Ordenar valores de cada faceta por frecuencia de aparición en los resultados (más comunes primero)

## Verification (post-implementation)

- [ ] Test unitario clasificador (50 queries, ≥90% aciertos)
- [ ] Test generación facetas (25 queries ambiguas, todas devuelven 3-5 facetas válidas)
- [ ] Test ordenación valores (verifica orden descendente por count)
- [ ] Test feature flag (cambio runtime sin redeploy)
- [ ] Test latencia (p99 ≤195ms con flag activo)
- [ ] Test regresión (diff vs baseline = 0 con flag desactivado)
- [ ] Documentación del schema actualizada
